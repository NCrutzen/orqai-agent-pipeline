# Phase 112.5 Plan 03: Pure signal-pipeline kernmodules Summary

One-liner: de drie swarm-agnostische, replay-veilige kernmodules van de passieve feedback-loop — `extractTransitions` (ruwe Graph delta-events -> Transition[] met cross-folder + split-over-ticks correlatie), `deriveSignals` (Transition[] + ledger-hit-set + per-swarm weights -> ReviewSignal[], waarbij een restore-met-ledger-hit = correctie_false_positive en zonder hit = restore_other), en een dunne `delta-client` (per-folder delta-paginatie met immutable-id prefer, bootstrap/410-suppressie + ancestry-aware folder-bucketing) — allemaal test-first gebouwd in `web/lib/email-behavior/` zonder enige sales-import.

## Wat is gebouwd

**Task 1 — `transition-extract.ts` + test (TDD, SC-1)** — commit `0d63fcfa`
- `extractTransitions(input): Transition[]` — bouwt `leftFolders`/`enteredFolders` Maps op immutable id (RESEARCH Pattern 2). Correleert within-tick (`@removed:deleted` + verschijning) én split-over-ticks via `lastKnownBucket` (Pitfall 3).
- Transitie-soorten: `moved_to_afgehandeld` (inbox→afgehandeld), `self_archived` (inbox→archive), `restored_from_archive` (archive→inbox), `category_edited` (categories-diff tegen prevCategories), `read_aged` (isRead false→true zonder move), `replied` (sent-bucket created-event met conversationId-match → gekoppeld aan inbound `matched_email_id`).
- Puur: `observed_at` is parameter, geen clock/random, geen sales-constanten. 10 vitest-cases groen (RED-first; 8 plan-behaviors + 2 negatieve gevallen).

**Task 2 — `signal-derive.ts` + test (TDD, SC-2)** — commit `939dcc7d`
- `deriveSignals(input): ReviewSignal[]` — ledger-join (Pitfall 5): `restored_from_archive` + email_id in `ledgerHits` = `correctie_false_positive`; zonder hit = `restore_other`. `category_edited` → `reclassify` (category_key uit `categories[0]`); `moved_to_afgehandeld` → `approve_handled`; `replied` → `approve_replied`; `self_archived`/`read_aged` → weights-afhankelijk.
- `DEFAULT_WEIGHTS` const + optioneel `weights`-argument; effectief = `{ ...DEFAULT_WEIGHTS, ...override }`. `SignalWeights`-type categorisch.
- Deterministische `dedupe_key = ${swarm_type}|${email_id}|${verdict}|${observedTickIso}` (swarm_type-isolatie, Plan 02 T-112.5-14). 8 vitest-cases groen (RED-first).

**Task 3 — `delta-client.ts` + bootstrap/410-test** — commit `dfafe26a`
- `deltaPage(opts)` — pagineert één per-folder delta-stroom via `@odata.nextLink` → `@odata.deltaLink`, roept `graphFetch` aan MET `prefer` (immutable-id). Bootstrap (`deltaLinkOrNull=null`) of vervolg vanaf deltaLink. Vangt 410 (`resyncRequired`/`SyncStateNotFound`) → gooit token weg, herstart als bootstrap, zet `wasBootstrap=true` (signal-suppressie, Pitfall 2). Elk event krijgt `_folderId`-context.
- `resolveFolders(mailbox)` — RECURSIEVE childFolders-walk over de hele boom; geeft `{ folder_id, display_name, path }[]` met display-name-keten (112.5-01: afgehandeld leeft in geneste jaar-submappen).
- `bucketForFolderPath(path)` — ancestry-aware: pad met een 'afgehandeld'-segment erft de afgehandeld-bucket; anders `bucketForFolderName` van het laatste segment.
- Mailbox is parameter, geen sales-imports. 7 mock-tests groen (bootstrap / paginatie / vervolg / 410-resync / 3× ancestry).

## DEFAULT_WEIGHTS (operator-besluit, vastgelegd)

Conform het 112.5-01 operator-besluit ("weging akkoord", 2026-06-04) zijn de defaults:

| transition_kind | verdict (default) | weging |
|---|---|---|
| restored_from_archive + ledger-hit | correctie_false_positive | sterkst |
| restored_from_archive zonder hit | restore_other | n.v.t. (geen leersignaal over ons systeem) |
| moved_to_afgehandeld | approve_handled | sterk |
| category_edited | reclassify | sterk |
| replied | approve_replied | sterk |
| self_archived | weak_seen (`DEFAULT_WEIGHTS.self_archived = "weak_noise"`) | zwak |
| read_aged | weak_seen (`DEFAULT_WEIGHTS.read_aged = "weak"`) | zwakst |

**Override:** een swarm zet `behavior_tracking_config.weights` (Plan 02 jsonb-kolom); de worker (Plan 04) merget die over `DEFAULT_WEIGHTS`. Bewezen in Test 6: `{ self_archived: "strong_noise" }` geeft `approve_handled` i.p.v. de default `weak_seen`.

## Deviations from Plan

**1. [Rule 3 - Blocking, design] delta-client gebruikt een eigen `DeltaEvent`-interface i.p.v. import van `transition-extract.RawDeltaEvent`.**
- Found during: Task 3.
- Issue: rechtstreeks importeren zou een module-koppeling leggen tussen de IO-wrapper en de pure helper; de plan-action beschrijft beide als losse modules met structureel compatibele shapes.
- Fix: `delta-client.ts` definieert een lokale `DeltaEvent` (zelfde velden + `_folderId`). De worker (Plan 04) geeft `DeltaEvent[]` door als `RawDeltaEvent[]` — structureel typecompatibel (tsc clean).
- Files: `web/lib/email-behavior/delta-client.ts`. Commit: `dfafe26a`.

**2. [Rule 2 - Missing critical] `deriveSignals` kreeg een `emailIdOf`-resolver-parameter.**
- Found during: Task 2.
- Issue: de plan-spec zegt "de worker geeft observedTickIso + swarmType mee", maar voor `replied` moet het signaal aan het INBOUND email_id hangen (niet het sent-bericht) en in het algemeen is `immutable_id` niet per se gelijk aan het pipeline `email_id`. Zonder resolver zou de pure helper DB-kennis nodig hebben.
- Fix: `emailIdOf: (immutableId) => string` toegevoegd aan `DeriveInput`; `replied` gebruikt `matched_email_id`, de rest `emailIdOf(immutable_id)`. Houdt de helper puur en DB-onwetend.
- Files: `web/lib/email-behavior/signal-derive.ts`. Commit: `939dcc7d`.

**Totaal: 2 auto-fixes (1 design-isolatie, 1 missing-critical parameter). Geen architectuur-wijzigingen (Rule 4). Impact: beide houden de modules puur en swarm-agnostisch; geen scope-uitbreiding.**
