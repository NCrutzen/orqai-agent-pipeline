# Phase 112.5 Plan 04: registry-driven Outlook behaviour delta-sync worker Summary

One-liner: de durable, REGISTRY-DRIVEN Inngest delta-sync worker (`swarm/behavior-sync`) die de Plan 02 datalaag en de Plan 03 pure helpers bedraadt tot één swarm-generieke engine — cron business-hours + event-triggerbaar, itereert ALLE `public.swarms`-rijen met `behavior_tracking_config.enabled=true` (0 hardcoded swarm-literals), bootstrap't ancestry-aware de folder-map, pollt per folder delta met token-persist binnen de step, leidt transities + verdict-signalen af (incl. restore=`correctie_false_positive` via een swarm_type-scoped stage-4 ledger-join) en schrijft idempotent (23505 no-op) naar `swarm_email_transitions` + `swarm_review_signals` met Sugar-skip en replay-veilige ids.

## Wat is gebouwd

- `swarmBehaviorSync = inngest.createFunction({ id: "swarm/behavior-sync", retries: 1, concurrency: { limit: 1 } }, [{ cron: "TZ=Europe/Amsterdam */5 6-19 * * 1-5" }, { event: "swarm/behavior-sync.requested" }], handler)`. De cron-string staat op de trigger-arg (een plain `const CRON_BUSINESS_HOURS`), NOOIT in een `/* */` JSDoc.

- **(3) Folder-map bootstrap:** als `loadFolderMap` leeg is -> `resolveFolders(mailbox)` (recursief) -> `bucketForFolderPath(path)` (ancestry-aware: jaar-submappen onder afgehandeld erven de bucket) -> `upsert` in `outlook_folder_map` (`onConflict folder_id`, met `mailbox`-kolom). - **(4) Per-folder delta:** eigen `step.run("delta-${swarmType}-${folderId}")`: token-rij laden, `deltaPage({ deltaLinkOrNull, prefer: 'IdType="ImmutableId", odata.maxpagesize=100' })`, nieuwe deltaLink + `bootstrapped=true` upserten BINNEN de step (Phase 65). `wasBootstrap` -> 0 events doorgeven (signal-suppressie, Pattern 1). Lean events over de boundary.
- **(5) derive-and-write:** `bucketOf` via `loadFolderMap`; `lastKnownBucket` uit prior `swarm_email_transitions` (chunked `.in(150)`); immutable_id -> email_id via `email_pipeline.emails` (`source='outlook' AND mailbox`); `extractTransitions(observed_at=tickIso)`; ledger-join `pipeline_events.select("email_id").eq("swarm_type", swarmRow.swarm_type).eq("stage", 4).in("email_id", restoredEmailIds)`; `deriveSignals({ ledgerHits, swarmType, weights })`.
- **(6) Idempotente inserts:** `swarm_email_transitions` + `swarm_review_signals` met de 23505 no-op try/catch. NOOIT `.insert/.upsert/.update` op `pipeline_events` (alleen `.select`).
- **(7) Counts per swarm** (transitions_written, signals_written, by_verdict, bootstrapped_folders, skipped_sugar). Geregistreerd in `route.ts` (import + functions-array).
