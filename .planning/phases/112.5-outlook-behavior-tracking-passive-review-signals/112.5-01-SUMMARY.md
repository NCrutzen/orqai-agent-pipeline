# Phase 112.5 Plan 01: Folder-conventie-analyse Summary

One-liner: een swarm-agnostische pure aggregator (`aggregateFolderConvention` + `bucketForFolderName`) plus een read-only one-shot Inngest report-worker (`salesEmailFolderConvention`) die de verkoop@smeba.nl corpus over inbox/archive/afgehandeld-buckets telt en een afgehandeld-vs-archive ratio teruggeeft — zonder enige write naar live-pipeline state.

## Wat is gebouwd

**Task 1 — `web/lib/email-behavior/folder-convention-report.ts` (+ Wave-0 test)** — commit `985cbb39`
- `aggregateFolderConvention(rows)`: pure per-bucket counts, `afgehandeld_total`, `archive_total`, `afgehandeld_vs_archive_ratio` (null bij deling-door-nul, nooit NaN), `total_classified`, `other_count`. Onbekende buckets → 'other', uitgesloten uit de ratio.
- `bucketForFolderName(displayName)`: pure jaartal-collapse mapper; elke `afgehandeld {jaar}` → `'afgehandeld'`. EN+NL well-known namen.
- Swarm-agnostisch: nul sales-constanten, geen clock/randomness, geen IO. 8 vitest-cases groen (RED-first).

**Task 2 — `web/lib/inngest/functions/sales-email-folder-convention.ts` + route/events** — commit `526bfdb2`
- `salesEmailFolderConvention`: event `sales-email/folder-convention.requested`, `concurrency: { limit: 1 }`, `retries: 3`.
- Read-only: enumereert de folder-tree één keer (top-level + één laag childFolders), selecteert de corpus-email_ids+source_ids (`source='outlook'` AND `mailbox='verkoop@smeba.nl'`, niet-null `source_id`), resolvet `parentFolderId` per message in batches van 150, buckett via `bucketForFolderName`, aggregeert via de generieke helper.
- Side-channel isolation: GEEN `.insert/.upsert/.update` — geeft het rapport terug als function-output + logt het.
- Sales-targeted invocatie (verkoop@smeba.nl pin in de worker, NIET in de helper). Sugar-rijen uitgesloten door `source='outlook'`. Graph 400/404 per message = no-op skip (geteld als `unresolved`).
- Replay-safe `run_id` IN `step.run`; ids-only over step-boundaries; chunked `.in(150)`.
- `graphFetch` geëxporteerd (additief) + optionele `prefer`-param voor `IdType="ImmutableId"`.

## Checkpoint — RESOLVED 2026-06-04 (operator: "weging akkoord")

**Analyse-uitkomst (live run, 905 corpus-mails, 100% resolved):** inbox 170 · archive 65 · afgehandeld 0 · other 670. De "0 afgehandeld / 670 other" bleek een bucketing-artefact: de team-conventie leeft in GENESTE jaar-submappen — `Inbox/afgehandeld/{2024: 21.636, 2025: 8.322, 2022/23: 22.478, ouder: ~6.2k}` (~58k mails) — terwijl Outlook-Archief slechts 80 items telt (waarvan ~67 door ons systeem). **Conclusie: de conventie is zéér consistent; afgehandeld-boom = afgehandeld, Archief ≈ exclusief systeem-noise.**

**Vastgestelde weging (operator):** moved_to_afgehandeld = approve_handled (sterk) · restored_from_archive + ledger-hit = correctie_false_positive (sterkst) · category_edited = reclassify (sterk) · replied = approve_replied (sterk) · self_archived = zwak noise-signaal (team archiveert zelf vrijwel nooit) · read_aged = weak_seen (zwakst).

**Design-gevolg (geamendeerd in Plans 03/04):** resolveFolders wordt een recursieve tree-walk die `path` meegeeft; bucketing wordt ancestry-aware (`bucketForFolderPath`) zodat jaar-submappen de afgehandeld-bucket erven.
