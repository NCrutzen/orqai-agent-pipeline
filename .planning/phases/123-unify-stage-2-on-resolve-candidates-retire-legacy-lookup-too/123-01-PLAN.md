resolve_candidates input + match shape (web/lib/automations/debtor-email/nxt-zap-client.ts):
```typescript
export type ResolveCandidatesInput = {
  nxt_database: string;
  brand_id: string;          // ^[A-Z]{2}$
  environment_id: string;    // hard scope filter, e.g. "BX"
  identifiers: string[];     // the seeds (here: domain/address, or invoice numbers)
  brand_scope?: string[];    // tiebreaker, never a hard pre-filter
};
export const lookupResolveCandidates =
  (input: ResolveCandidatesInput, intent: string) =>
    callNxtTool("nxt.resolve_candidates", input, intent);

export type ResolveCandidateMatch = {
  identifier_kind: string;          // e.g. "email_domain" | "email_address" | "invoice_no"
  identifier_value_norm: string;
  party_id: string;                 // composite, e.g. "BX593290"
  party_name: string;
  scope_key?: string | null;
  brand_id?: string | null;
  parent_party_id?: string | null;
  root_party_id?: string | null;    // D-04 rollup target; null = already a root
  is_unique_in_scope: boolean;      // proc verdict per DIRECT party_id
  precedence?: string | null;
  status?: string | null;
};
```

The proven self-auth pattern to MIRROR for the sender step (web/.../resolve/steps/self-auth-match.ts):
- read once via `lookupResolveCandidates({ nxt_database, brand_id, environment_id: config.scope.environment_id, identifiers, brand_scope: args.brand_scope }, "unknown")`
- `.catch(() => ({ matches: [] as ResolveCandidateMatch[] }))` graceful fall-through
- filter `m.is_unique_in_scope && isAutoEligibleStatus(m.status)` and `eligibleSet.has(m.identifier_kind)`
- dedupe distinct parties; `!== 1` → return null (SUGGEST, fail-closed)
- prefix-family gate via `inPrefixFamily(winner.brand_id, inScopeBrands)` where inScopeBrands = `new Set([args.brand_id, ...(args.brand_scope ?? [])])`
- `stripEnvPrefix(winner.party_id, config.scope.environment_id)` → numeric customer_account_id
- carry `environment_id` on the result (D-02)
