<objective>
Refactor `swarm-behavior-sync.ts` from a single shared run that iterates every
`(swarm x mailbox)` sequentially under `concurrency:{limit:1}` into a fan-out
topology: a thin cron orchestrator that emits one event per enabled
`(swarm x mailbox)`, and a per-mailbox worker that processes exactly one mailbox
per invocation. This gives true fault isolation (one mailbox's throw is its own
failed run) and removes the shared wall-clock/step budget (no mailbox can starve
the rest). Add a VISIBLE per-mailbox terminal-failure telemetry sink so a failure
is never silent again.

Purpose: Fix the confirmed 2026-06-16 production regression where enabling the
debtor swarm's 4 mailboxes starved the shared single-run loop and froze the
previously-healthy sales `verkoop@smeba.nl` observe. Both fault-isolation AND
fair-budgeting are mandatory (119-CONTEXT.md LOCKED decisions).

Output: a thin orchestrator + per-mailbox worker in
`swarm-behavior-sync.ts`, both registered in the Inngest serve route, with a
visible per-mailbox failure telemetry row, and an updated runbook. Tests are
delivered in Plan 119-02.
</objective>
