<objective>
Reconcile sales into the generic corroboration capability (the trickiest SWARM-02 constraint) AND switch sales identifier lookups from REST to the SQL `resolver_index` back-search. These are INSEPARABLE (Pitfall 3): sales corroboration cannot fire over `nxtRequest` REST because each REST lookup returns at most one customer with NO `identifier_kind`/`is_unique_in_scope` metadata — independence (D-05) is uncomputable. Migrate the transport FIRST so each sales lookup returns rows carrying `identifier_kind` + `is_unique_in_scope` + `party_id` (the same shape the engine corroboration consumes), then route the sales adapter's own loop through the SHARED `scoreCorroboration` helper when `config.corroboration` is present — gated on config DATA, not swarm name (CORR-04).

Purpose: sales opts into corroboration without a per-swarm branch (SWARM-02 holds) and without the `512887` REST false positive.
Output: 3 migrated lookups (offerte/order/sites), the sales adapter collect path, and 4 new tests.
</objective>
