<objective>
Wire the actual Stage-4 forward side-effect: a swarm-agnostic Inngest worker that reads the
Phase-131 verdict, applies the three hard skips, honors the per-bucket gate + dedup +
forward-state idempotency, does the createForward→PATCH replyTo→send draft flow, and stamps
the source mail. The coordinator emits a dedicated `pipeline/forward.requested` event after
persisting the verdict (decoupled from the held `stage_3_routing` gate — RESEARCH A4).

Purpose: This is the phase's core side-effect. It turns the persisted verdict into a real
forward, gated per-bucket and idempotent on replay (D-02). The forward worker is a near-clone
of the Phase-117 intent-label worker skeleton.

- `stage-4-info-routing-forward.ts` worker (listens on `pipeline/forward.requested`)
- `forward-state.ts` idempotency store + its backing `info_routing_forwards` table migration

- Coordinator forward-request emit (one new step after persist-routing-verdict)
- SWARM-02 static guard extended to cover the forward worker
- Worker registered in the Inngest serve array
