# Phase 132.1 Plan 01: Stage-3 Dispatch-Wiring Fix + Held-Path Stamp/Baseline Summary

Generic `email_id` resolution from `message_id` at the coordinator entry (kills the `createRun: null email_id` crash class) plus a held-path `AI: held → <bucket>` / `AI: triage` Outlook category stamp + `swarm_written_categories` baseline that breaks the D-01 chicken-and-egg — both swarm-agnostic, zero swarm-name branches.

## What Was Built

### Task 1 (D-fix) — email_id resolution from message_id
`web/lib/inngest/functions/debtor-email-coordinator.ts`: a generic `const resolvedEmailId = email_id ?? (await step.run("resolve-email-id", ...))` fallback inside a replay-safe `step.run` that clones the Stage-2 `.or(source_id.eq.<message_id>,internet_message_id.eq.<message_id>)` PostgREST query (does NOT import the resolver). When `email_id` is absent and resolution returns null it throws `coordinator: unresolved email_id for message_id=<id>` BEFORE `createRun` — fail loud, no NULL INSERT (T-132.1-04). `resolvedEmailId` is threaded through `createRun`, the `coordinator_runs` insert, the dedup read, every `emitPipelineEvent`, the forward emit, the intent-classify reads, the intent-label emit, all `pipeline/predicted` emits, and every return. Byte-neutral for debtor/sales (email_id present → fallback skipped). `pipeline/coordinator.requested` event type updated: `email_id` optional + `message_id?` added.

### Task 2 (D-01 / D-04) — held-path stamp + 112.5 baseline
Inside the held branch (`routingGatedForRouting`), a new best-effort isolated `step.run("stamp-held-routing-category", ...)` runs BEFORE `mark-routing-verdict-held`. It builds `AI: held → <bucket>` (routable) or `AI: triage` (unrouted) via `buildRoutingCategory`, GETs+PATCHes the source mail's categories via `graphFetch` (resolving the source mailbox + Graph immutable id from the emails row the same way the forward worker does), and seeds the `swarm_written_categories` baseline via `recordWrittenCategory` with the same category string. The matched no-forward `algemeen` case (target_mailbox null AND not unrouted) is skipped — no forward measurement axis (D-04). The whole step is wrapped in try/catch so a Graph failure never aborts the held-verdict persist (best-effort isolation, mirroring the forward worker). Byte-neutral for debtor/sales (routing block skipped on empty routing_destinations).
