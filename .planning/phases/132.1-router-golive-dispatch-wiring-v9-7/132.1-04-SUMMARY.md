# Phase 132.1 Plan 04: Shadow Ground-Truth Wiring + Per-Mailbox Forward Auto-Flip Summary

Wires the ROUTE-08 shadow harness `human_category` to the real 112.5 delta-synced operator correction (keyed by `email_id`, mapped to a bucket via `categoryToBucket`) with the gate logic byte-unchanged, and builds the per-mailbox auto-flip cron that releases `stage_4_forward_buckets` at ≥85% precision with a hard `graded_n≥50` guard — brand-reachable, release-only, idempotent, with a precision-regression monitor and the Plan-03 one-flag revert as the panic lever.

## What Was Built

### Task 1 (ROUTE-08 / D-01) — human_category wired from the operator correction
`web/scripts/eval/info-routing-precision-shadow.ts`:
- `mapRowToShadow` no longer hard-nulls `human_category`. It now takes `categoryToBucket` + `humanCategoryByEmailId` and resolves `human_category = categoryToBucket.get(capturedCategory) ?? null`. A row with no captured correction, or one mapping to no routing bucket, stays `null` (ungraded) — so `graded_n` only counts emails the operator actually corrected.
- `buildCategoryToBucket(destinations)` inverts `routing_destinations.outlook_category → destination_key` (the master colour categories: Verkoop, Storingen, …) AND seeds the AI routing-label vocabulary (`AI: routed → <bucket>`, `AI: held → <bucket>`) → bucket, so a correction maps whether the operator applied a master colour OR edited the Plan-01 AI held stamp. The `unrouted` sentinel (null `outlook_category`) is skipped.
- `COORDINATOR_RUNS_SELECT` now carries `email_id` (the join key to the 112.5 correction) + `source_mailbox` (the per-mailbox grouping axis) + `decision_details`. The non-existent `human_outlook_category` column (BUG 3 / WR-05) is still never selected.
- `computePerMailboxStats` groups `ShadowRow`s by `source_mailbox` and grades EACH mailbox independently via the UNCHANGED `computeMatchRate` + `gradeVerdict` — precision is measured PER MAILBOX, not swarm-wide. The false-success guard applies per mailbox (a small sample → `insufficient_sample` → can never flip).
- `main()` now reads the 112.5 corrections from `swarm_review_signals` (`transition_kind='category_edited'`, `category_key not null`, ascending `observed_at` so the latest correction wins), builds the email_id→category map, projects rows, and reports both the swarm-wide verdict AND a per-mailbox breakdown.
- `computeMatchRate`, `gradeVerdict`, `MIN_GRADED_N=50`, `MATCH_RATE_GATE=0.85` are byte-unchanged (asserted in tests).

### Task 2 (D-02) — per-mailbox forward auto-flip cron
`web/lib/inngest/functions/info-routing-forward-autoflip.ts` (registered in `web/app/api/inngest/route.ts`):
- A business-hours cron (`TZ=Europe/Amsterdam */30 6-19 * * 1-5`, serial concurrency:1) + a manual `info-routing/forward-autoflip.requested` event trigger.
- Loads the routing registry + the swarm's FRESH `dry_run_config` (not the cached `loadSwarm`) + `resolution_config.scope.entity_by_mailbox` (mailbox→brand). Reads the same shadow inputs as the harness, grades per mailbox via the imported pure fns.
- `planForwardBucketFlips` (pure, in the harness): for each mailbox with `status==='graded' && pass===true && graded_n>=MIN_GRADED_N`, releases the brand-reachable buckets (`releasableBucketsForBrand` — the cleared mailbox's brand's active destination buckets, sentinel excluded). Idempotent (skips buckets already `true`) and release-only.
- Applies the releases with a re-read-then-spread-merge of `dry_run_config` that sets ONLY the target bucket keys to `true` — every sibling (`stage_3_routing`, `stage_2_resolution`, …) preserved. No flips → no write.
- Monitoring: emits a `pipeline_events` row `forward_autoflip_precision_regression` (stage 4, `email_id` null) when a mailbox whose brand has an already-released bucket now grades `pass===false` (post-release regression). The alert names the Plan-03 `20260624b` revert migration as the panic lever. The cron never auto-reverts (release-only).
- gradeVerdict is IMPORTED, not reimplemented; SWARM-02 grep gate clean (data-gated, zero literal `swarm_type === 'info-routing'` branch).

## Decisions Made

- **Ground-truth source** — `swarm_review_signals` (the durable 112.5 `reclassify` output) joined by `email_id`, NOT `coordinator_runs` (which has no human-category column) and NOT a new schema column. This keeps the change inside the plan's `files_modified` set (harness + cron + route) with no migration.
- **Brand-reachable reconciliation (Option A)** — operator-confirmed via the Task-1→Task-2 checkpoint. `stage_4_forward_buckets` stays keyed by bucket alone; a cleared mailbox releases the bucket key when any of its brand's reachable rows clears. No per-(bucket×brand) registry key-shape change.
