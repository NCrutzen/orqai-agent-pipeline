# Phase 132.1 Plan 03: Info-Routing Router Activation Summary

Two migration-only registry flips (D-fix dispatch re-flip + D-01 behavior-tracking enable as jsonb `||` merges, siblings preserved) plus the D-02 one-flag forward-bucket revert (armed, not applied), and a registry-sourced one-shot entrypoint that invokes Plan-02's inert `ensureRoutingMasterCategories` on both info@ mailboxes to bring the D-03 non-grey routing colour live — all gated on Plan-01's email_id resolution so the 24-fail crash does not return.

## What Was Built

### Task 1 (D-fix + D-01) — activation migration
`supabase/migrations/20260624a_phase1321_info_routing_activation.sql`:
- **(1) Dispatch re-flip** — `UPDATE swarm_noise_categories SET action='swarm_dispatch', swarm_dispatch='pipeline/coordinator.requested' WHERE swarm_type='info-routing' AND category_key='unknown'`. The `unknown` row stays a Stage-1 noise row (hard-separation invariant). A long header documents the hard dependency on Plan 01's `email_id ?? resolve-from-message_id` fallback (commit 049e6207/a5526406) and cites the 24-fail/24h incident — re-flipping before that fix reproduces the NOT-NULL crash (Pitfall 2 / T-132.1-09).
- **(2) Behavior-tracking enable** — `UPDATE swarms SET behavior_tracking_config = behavior_tracking_config || '{"enabled": true, "mailboxes": ["info@smeba.nl","info@fire-control.nl"]}'::jsonb WHERE swarm_type='info-routing'`. The `||` merge preserves any sibling keys (T-132.1-08). 112.5 reads `cfg.mailboxes ?? [cfg.mailbox]` (Phase 118 string-array form).
- Deliberately does NOT touch `dry_run_config.stage_3_routing` (stays true/held — no swarm_intents, opening it throws on empty ranked[]) nor `stage_4_forward_buckets` (stays {} / all-held).

### Task 2 (D-03) — colour go-live invocation entrypoint
`web/scripts/ensure-info-routing-categories.ts` — the activation home for Plan-02's `ensureRoutingMasterCategories`:
- Loads active routing buckets from the `routing_destinations` registry via `loadRoutingDestinations(admin, 'info-routing')` (NO hard-coded list), excludes the `unrouted` framework sentinel, de-dupes + sorts.
- Invokes `ensureRoutingMasterCategories(mailbox, buckets)` once per `info@smeba.nl` and `info@fire-control.nl`, provisioning routing master-categories with the chosen non-grey **`preset5`** (`ROUTING_CATEGORY_PRESET_COLOR`, recorded by Plan 02 — NOT `preset0`/grey).
- Idempotent by construction (GET-before-POST in Plan 02); safe to re-run to prove idempotency (additive-only POST of missing names, never PATCH/delete — T-132.1-11).
- `--dry-run` flag prints the registry-derived bucket set without any Graph write.

### Task 3 (D-02) — one-flag forward revert migration
`supabase/migrations/20260624b_phase1321_forward_buckets_revert.sql`:
- Single statement: `UPDATE swarms SET dry_run_config = jsonb_set(dry_run_config, '{stage_4_forward_buckets}', '{}'::jsonb) WHERE swarm_type='info-routing'`. Resets the per-bucket release map to empty = all held (fail-closed; `isForwardBucketReleased` requires `=== true`).
- `jsonb_set` on exactly the `{stage_4_forward_buckets}` path → `stage_3_routing` and every other `dry_run_config` sibling preserved (T-132.1-08).
- Armed but intentionally **NOT applied** during normal activation — it is the panic flip-back lever referenced by the Plan-04 gated auto-flip monitoring.
