<objective>
Insert the extraction funnel step (D-01/D-02) between the Stage 1 verdict and the Stage 2 request, with ZERO change to the verdict worker. The classifier verdict worker already fires the event named in `swarm_noise_categories.swarm_dispatch`. Rewire sales' `unknown` category's `swarm_dispatch` (registry data) to `sales-email/attachments.extract.requested`; a new worker listens there, runs extraction for captured attachments (registry-gated), updates rows, then re-emits the downstream Stage 2 event **whose name it reads from `attachment_config.stage2_dispatch_event` (registry, Plan 01) — never a code literal**. When the registry `extract` switch is OFF, it passes straight through (emits the Stage 2 event immediately) — so any swarm whose dispatch points here but has extract=OFF behaves identically to before.

Purpose: Closes SC-2 / ATTACH-02 — content extraction is a uniform, registry-keyed funnel step with no swarm-specific branches. The runtime change is one registry UPDATE + one new worker; the shared verdict worker is untouched. The per-email download→store→extract loop is factored into `extract-worker.ts` so Plan 06 backfill shares the exact same implementation (no drift — checker cross-plan-contract fix).
Output: Shared extract-worker helper + new extractor worker + registry rewire migration + worker registration + unit tests.
</objective>
