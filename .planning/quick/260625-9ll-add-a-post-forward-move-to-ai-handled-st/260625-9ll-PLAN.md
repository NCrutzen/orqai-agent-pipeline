# Quick 260625-9ll — Move auto-forwarded info@ mail to "AI Handled"

The live-mode terminal action of the operator spec is `released bucket → label → forward → MOVE`
(memory `move-auto-handled-info-mail-to-ai-handled-folder`). The Stage-4 forward worker today does
label + forward but NOT the move. Add it.

## Task 1 — Graph helper `moveMessageToFolder`
- **files:** `web/lib/outlook/client.ts`
- **action:** Add `moveMessageToFolder({ mailbox, messageId, folderName })`. Resolve the destination
  folder id by display-name under the mailbox's mailFolders (create it if absent), caching the
  resolved `(mailbox, folderName) → folderId` (module Map, like other helpers). Then
  `POST /users/{mailbox}/messages/{messageId}/move` with `{ destinationId }`. Return the existing
  `OutlookActionResult` shape (`{ success, error? }`) — never throw.
- **verify:** `cd web && npx tsc --noEmit`; a unit test for the pure folder-id cache/resolve seam if
  feasible without live Graph.
- **done:** helper exported, typechecks.

## Task 2 — Wire the move into the forward worker
- **files:** `web/lib/inngest/functions/stage-4-info-routing-forward.ts`
- **action:** After the existing `record-forward-state` + `stamp-category` steps (i.e. only on the
  forwarded path, which is already inside the released+routable+forwarded branch), add a NEW
  `step.run("move-to-ai-handled", …)` that calls `moveMessageToFolder({ mailbox, messageId: graphId,
  folderName: "AI Handled" })`. Best-effort: wrap so a move failure is swallowed (mirrors the
  best-effort stamp) and NEVER affects the forward/`forward_state`/return decision. Do NOT change the
  forward, stamp, dedup, gate, or any skip/held path.
- **verify:** `cd web && npx tsc --noEmit`; confirm the move step is unreachable on held/skip/dry-run
  paths (it sits after the forward-success guard).
- **done:** released+forwarded mail moves to "AI Handled"; all other paths unchanged.
